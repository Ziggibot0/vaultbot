# Orchestration Metrics

> Defined as part of issue #365 — *[observability] Add per-turn orchestration attribution (route, cost, latency)*.

This page documents the three first-class orchestration attribution events
emitted by `SessionLogger` for every completed turn, plus the report utility
that aggregates them.

---

## Events

### `route_decision`

Emitted once per turn immediately after the pre-router decides which execution
path to take.

| Field | Type | Description |
|---|---|---|
| `route` | `str` | Chosen path: `deterministic`, `small_model`, `procedure`, or `big_model` |
| `confidence` | `float` | Router confidence in `[0, 1]` |
| `reason` | `str` | Short reason code (e.g. `action_signal`, `clarification_or_explanation`, `mixed_or_unsettled`) |
| `turn_index` | `int?` | 1-based turn counter (omitted when not tracked by caller) |

**Example**
```json
{
  "event": "route_decision",
  "session_id": "…",
  "timestamp": 1724000000.0,
  "data": {
    "route": "procedure",
    "confidence": 0.85,
    "reason": "action_signal",
    "turn_index": 3
  }
}
```

---

### `turn_cost`

Emitted once per turn after the agentic loop completes.

| Field | Type | Description |
|---|---|---|
| `prompt_tokens` | `int` | Tokens sent to the model in this turn |
| `completion_tokens` | `int` | Tokens generated by the model |
| `total_tokens` | `int` | `prompt_tokens + completion_tokens` |
| `tool_latency_ms` | `float` | Sum of all tool-call wall-clock durations for this turn |
| `cost_usd` | `float?` | Estimated dollar cost (omitted when caller does not compute it) |
| `model` | `str?` | Model identifier (omitted when not supplied by caller) |
| `turn_index` | `int?` | 1-based turn counter |

Cost estimation is intentionally optional and left to the caller so that
different providers can use their own per-token rates without coupling this
module to billing logic.

**Example**
```json
{
  "event": "turn_cost",
  "session_id": "…",
  "timestamp": 1724000001.2,
  "data": {
    "prompt_tokens": 512,
    "completion_tokens": 128,
    "total_tokens": 640,
    "tool_latency_ms": 480.0,
    "cost_usd": 0.000192,
    "model": "gpt-4o-mini",
    "turn_index": 3
  }
}
```

---

### `turn_efficiency`

Emitted once per turn, summarising routing efficiency.

| Field | Type | Description |
|---|---|---|
| `tool_rounds` | `int` | Number of LLM→tool round-trips in this turn |
| `completion_outcome` | `str` | Outcome label: `success`, `fallback`, `error`, `truncated` |
| `repeated_tool_calls` | `list[str]` | Tool names called more than once (signals routing inefficiency) |
| `turn_index` | `int?` | 1-based turn counter |

**Example**
```json
{
  "event": "turn_efficiency",
  "session_id": "…",
  "timestamp": 1724000001.3,
  "data": {
    "tool_rounds": 2,
    "completion_outcome": "success",
    "repeated_tool_calls": [],
    "turn_index": 3
  }
}
```

## Report Utility — `orchestration_report.py`

`session_orchestration_report(log_path, *, baselines=None)` reads a session
JSONL log and returns a dict with:

| Key | Description |
|---|---|
| `session_id` | Session UUID |
| `turns` | List of per-turn attribution dicts (merged from the three events above) |
| `summary` | Session-level rollup (see below) |
| `comparisons` | Deltas vs optional baseline values |

### Summary fields

| Field | Description |
|---|---|
| `turn_count` | Total turns parsed |
| `route_distribution` | `{route: count}` map |
| `total_prompt_tokens` | Sum across all turns |
| `total_completion_tokens` | Sum across all turns |
| `total_tokens` | Sum across all turns |
| `total_tool_latency_ms` | Sum of `tool_latency_ms` across all turns |
| `avg_tool_latency_ms_per_turn` | Mean tool latency per turn |
| `avg_tool_rounds_per_turn` | Mean LLM→tool round-trips per turn |
| `turns_with_repeated_tool_calls` | Count of turns where `repeated_tool_calls` was non-empty |
| `completion_outcomes` | `{outcome: count}` map |
| `total_cost_usd` | Sum of `cost_usd` across turns (only present when ≥1 turn has cost) |
| `avg_cost_usd_per_turn` | Mean cost per turn (only present when cost data available) |

### Baseline comparisons

Pass `baselines` dict with any of:
- `cost_usd_per_turn`
- `tool_latency_ms_per_turn`
- `tool_rounds_per_turn`

The report will compute signed deltas (positive = worse than baseline).

### CLI

```
python -m orchestration_report <session-uuid>
python -m orchestration_report <session-uuid> --json
python -m orchestration_report <session-uuid> --sessions-dir /path/to/sessions
```

---

## Non-goals

- Full BI dashboard — this is a lightweight CLI/library utility only.
- Provider-specific billing exactness — cost estimates use configurable
  per-token rates supplied by the caller; no hardcoded billing tables.
